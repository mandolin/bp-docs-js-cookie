Guide · about 6 minutes

Build visitor language and theme preferences

Apply each choice immediately; persist it across visits only when possible, with a safe default for every failure branch.

First-party display stateNo user identity5 steps
Model settings, not production facts. Examples use `site_locale`, `site_theme`, 30 days, `path=/`, host-only scope, and `SameSite=Lax`. BP deployment, domain, and browser behavior have not been verified from production configuration.

00

Set the boundary

Store only non-sensitive display preferences

This flow handles only language and theme choices made by the visitor. Fix purpose, fields, and defaults first; do not put free text or arbitrary objects into a cookie.

Field allowlist for the owner-directed reference model
NameAllowed valuesFallbackPurpose
site_localezh-CN / enzh-CNCurrent site content language
site_themesystem / light / darksystemCurrent site visual theme
Excluded data

Names, session/token values, authentication/authorization, consent evidence, analytics, advertising identifiers, and complete request headers do not belong here.

01

Restore a saved choice

Read and validate before applying the UI

Treat cookie values as untrusted. Missing, damaged, or non-allowlisted values use the model default; process the two fields independently so one invalid value does not erase the other.

Preference restore · concept exampleRun in the browser client
// <lang zh-CN>枚举集合定义可进入界面状态的唯一取值。</lang>
// <lang en>These sets define the only values allowed to become UI state.</lang>
const localeValues = new Set(["zh-CN", "en"]);
const themeValues = new Set(["system", "light", "dark"]);

// <lang zh-CN>Cookie 值是不可信输入，先分别读取两项，不合并身份信息。</lang>
// <lang en>Cookie values are untrusted; read the two preferences independently and include no identity data.</lang>
const storedLocale = Cookies.get("site_locale");
const storedTheme = Cookies.get("site_theme");

// <lang zh-CN>只有 allowlist 命中才应用；未知或缺失值使用显式默认。</lang>
// <lang en>Apply only allowlisted values; missing or unknown values use explicit defaults.</lang>
const locale = localeValues.has(storedLocale) ? storedLocale : "zh-CN";
const theme = themeValues.has(storedTheme) ? storedTheme : "system";

Outcome: each entry starts from a defined state; an untrusted cookie never decides DOM, styling, or execution paths.

02

The visitor makes a choice

Update this page first, then try to persist

Apply the allowlisted choice to the current page before calling `Cookies.set()`. The model example uses 30 days, a root path, host-only scope, and Lax; verify `Secure` and actual scope for the production HTTPS deployment.

Write example · illustrative defaultsNo browser persistence guarantee
// <lang zh-CN>selectedTheme 必须先通过 themeValues 校验；属性来自固定配置。</lang>
// <lang en>Validate selectedTheme against themeValues first; keep attributes in fixed configuration.</lang>
const preferenceAttributes = {
  expires: 30,
  path: "/",
  sameSite: "Lax",
  secure: window.location.protocol === "https:",
};

// <lang zh-CN>先完成当前页状态更新；set 调用不等于跨访问保存成功。</lang>
// <lang en>Update current-page state first; calling set does not prove persistence across visits.</lang>
Cookies.set("site_theme", selectedTheme, preferenceAttributes);
Give accurate feedback

“Applied on this page” is safe. Say “restored on your next visit” only after reading and confirming it; a serialized return value is not a browser persistence receipt.

03

The browser or environment refuses

Fall back to the current-page default; do not bypass policy

Missing / expired

Use the default

After expiry or site-data cleanup, take the first-visit branch. Core content remains available.

Invalid / decode error

Discard this field

Validate and isolate decode failures; do not loosen decoding repeatedly or switch to HTML execution.

Write blocked

Keep the current choice

Render from application state; do not claim cross-visit persistence or bypass privacy controls.

SSR / Node

Move to the client boundary

Do not access a missing `document` during build. Server reads need an explicit request API and scope.

What if the page runs in a third-party iframe?

Assume cookies may be blocked or partitioned. Evaluate CHIPS, Storage Access, and browser support only for a real product need; `SameSite=None` is not a permission bypass.

What if the requirement changes to login, authorization, or transactions?

Leave this preference flow. The server sets and protects authentication cookies; client js-cookie cannot read HttpOnly cookies. Writes need separate authorization and CSRF design.

04

The visitor resets or migrates

Reuse scope to remove; migrate old scope explicitly

Remove using the same `path` and `domain` (if set) as the original cookie. If older releases wrote the same name under another path/domain, define and verify a migration path rather than guessing its origin from the read result.

Removal exampleScope must match the write
// <lang zh-CN>使用与 set 相同的 path/domain 识别并移除偏好 Cookie。</lang>
// <lang en>Use the same path/domain as set to identify and remove the preference cookie.</lang>
Cookies.remove("site_theme", preferenceAttributes);
Do not clear unrelated cookies

Preference reset touches only `site_locale` and `site_theme`, not login, consent, shopping-cart, or other data.

API

Secondary reference

API used by this flow

Cookies.get(name)
Reads a named cookie visible to the current document; handle a missing value per its return contract.
Cookies.set(name, value, attributes)
Serializes and assigns a cookie; the browser decides final acceptance and retention.
Cookies.remove(name, attributes)
Expires a named cookie using matching path/domain attributes.
