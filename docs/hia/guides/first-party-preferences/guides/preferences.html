指南 · 约 6 分钟

实现访客语言与主题偏好

让访客选择立即生效；可恢复时再跨访问保留，并为每个失败分支设计安全默认。

00

先定边界

只保存非敏感的显示偏好

这个流程只处理访客明确选择的语言和主题。用途、字段与默认值在此固定；不要把自由文本或任意对象直接写进 Cookie。

负责人授权参考模型的字段 allowlist
名称允许值回退值用途
site_localezh-CN / enzh-CN当前站点内容语言
site_themesystem / light / darksystem当前站点视觉主题
排除数据

用户名、session/token、认证/授权、同意证明、analytics、广告追踪及完整请求头均不属于此流程。

01

恢复已有选择

读取后先校验，再应用界面

把 Cookie 值当作不可信输入。缺失、损坏或超出 allowlist 时回到模型默认；两个字段独立处理，一个异常不抹掉另一个有效选择。

偏好恢复 · 概念示例需在浏览器客户端执行
// <lang zh-CN>枚举集合定义可进入界面状态的唯一取值。</lang>
// <lang en>These sets define the only values allowed to become UI state.</lang>
const localeValues = new Set(["zh-CN", "en"]);
const themeValues = new Set(["system", "light", "dark"]);

// <lang zh-CN>Cookie 值是不可信输入，先分别读取两项，不合并身份信息。</lang>
// <lang en>Cookie values are untrusted; read the two preferences independently and include no identity data.</lang>
const storedLocale = Cookies.get("site_locale");
const storedTheme = Cookies.get("site_theme");

// <lang zh-CN>只有 allowlist 命中才应用；未知或缺失值使用显式默认。</lang>
// <lang en>Apply only allowlisted values; missing or unknown values use explicit defaults.</lang>
const locale = localeValues.has(storedLocale) ? storedLocale : "zh-CN";
const theme = themeValues.has(storedTheme) ? storedTheme : "system";

结果：每次入口都能从确定状态开始；非法 Cookie 不会决定 DOM、样式或执行路径。

02

访客作出选择

先更新当前页，再尽力写入

收到设置控件的选择后，先以已校验枚举更新当前页面，再调用 `Cookies.set()`。建议以 30 天、根路径、host-only 和 Lax 作为本模型示例；生产部署要单独确认 HTTPS 下的 `Secure` 与真实 scope。

写入示例 · illustrative defaults不承诺浏览器持久化
// <lang zh-CN>selectedTheme 必须先通过 themeValues 校验；属性来自固定配置。</lang>
// <lang en>Validate selectedTheme against themeValues first; keep attributes in fixed configuration.</lang>
const preferenceAttributes = {
  expires: 30,
  path: "/",
  sameSite: "Lax",
  secure: window.location.protocol === "https:",
};

// <lang zh-CN>先完成当前页状态更新；set 调用不等于跨访问保存成功。</lang>
// <lang en>Update current-page state first; calling set does not prove persistence across visits.</lang>
Cookies.set("site_theme", selectedTheme, preferenceAttributes);
访客反馈应准确

可以反馈“本页已应用”。只有重新读取并确认时，才说“下次访问已恢复”；不要把函数返回字符串描述为浏览器保存回执。

03

浏览器或环境不配合

降级到当前页默认，不绕过策略

缺失 / 过期

使用默认值

浏览器清理站点数据或 Cookie 到期后，重新走首次访问分支；核心正文不依赖它。

非法 / 解码异常

丢弃这一项

校验并处理解码失败；不反复宽松解码，也不让异常 Cookie 值进入界面。

写入被阻止

保留当页选择

继续以应用状态呈现；明确跨访问恢复不保证，不尝试绕过浏览器隐私策略。

SSR / Node

放到客户端边界

不要在构建阶段访问不存在的 `document`；服务端读取需走明确的 request API 与权限范围。

如果页面运行在第三方 iframe

把 Cookie 视作可能被阻止或分区。只有真实产品需要时才研究 CHIPS、Storage Access API 与目标浏览器支持矩阵；不要把 `SameSite=None` 当作绕过权限的开关。

如果需求转为登录、授权或交易

离开本指南的偏好流程。认证 Cookie 由服务端设置并保护；客户端 js-cookie 无法读取 HttpOnly Cookie。写操作还需独立授权和 CSRF 设计。

04

访客清除或版本迁移

复用 scope 清除，旧 scope 显式迁移

删除操作应使用写入时一致的 `path` 和 `domain`（如曾设置）。若历史版本曾在另一个 path/domain 写过同名 Cookie，先定义并核验旧 scope 清理策略，不假设读取结果能指出来源。

清除示例scope 必须与写入匹配
// <lang zh-CN>使用与 set 相同的 path/domain 识别并移除偏好 Cookie。</lang>
// <lang en>Use the same path/domain as set to identify and remove the preference cookie.</lang>
Cookies.remove("site_theme", preferenceAttributes);
不要顺手清空其它 Cookie

偏好重置只影响 `site_locale` 与 `site_theme`；不会触碰登录、同意、购物车或其它用途的数据。

API

次级参考

本流程用到的 API

Cookies.get(name)
读取当前文档可见的指定 Cookie；缺失时按返回契约处理。
Cookies.set(name, value, attributes)
序列化并赋值；浏览器仍决定最终接收与保留。
Cookies.remove(name, attributes)
用匹配的 path/domain 让指定 Cookie 立即过期。
