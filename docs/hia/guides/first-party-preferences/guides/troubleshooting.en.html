Troubleshooting · branch guide

Identify the condition, then follow its branch

When a cookie is missing, invisible, or blocked, the preference flow should recover rather than bypass a restriction.

29 representative scenariosCondition → branch → guide step
Coverage boundary: this is an owner-directed realistic model, not a count of BP production issues, browser certification, or user support records.
A

Read and validate

The value did not restore or selected an unexpected option

Missing

First visit, expiry, or site-data cleanup

Fall back independently to `zh-CN` and `system`, then allow a new choice. Cookies can be cleared early and are not a permanent database.

Back to step 01
Malformed

Unknown enum, truncated value, or decode error

Discard only the invalid field. Do not execute a string, inject HTML, or retry with permissive decoding.

Back to step 01
Partial

Language exists while theme is missing, or vice versa

Validate each field independently and retain a valid choice instead of resetting every preference.

Back to step 01
Concurrent / system

Two tabs or the system theme produce different results

Define entry reads and last-write behavior; js-cookie does not provide a cross-tab event protocol. Follow system only for `system`; explicit `light` / `dark` takes priority.

Back to step 02
B

Update and persist

The page changed, but the next visit did not

?
Separate “applied now” from “restored next time”

The application controls current-page state. Persistence also depends on expiry, scope, HTTPS, browser policy, and user cleanup.

The browser blocks writes. What should the UI say?

Keep the current choice and page content available. Say cross-visit restoration could not be confirmed, and do not try to bypass browser policy.

Production HTTPS behaves differently from local HTTP?

Verify `Secure` on production HTTPS and check localhost behavior separately. Do not generalize a local exception to a real host or include a real host in examples.

C

Path / Domain / migration

An old value appears, duplicates, or will not go away

Path changed

The site moved from root to a subpath

Fix the new write path; define and test cleanup for the old path. Path controls sending scope, not security.

Back to step 04
Subdomain isolation

Several subdomains need to share a preference

This model defaults to host-only. Confirm product need and trust boundaries before widening Domain scope.

Back to step 00
Old scope

The same name was written under multiple scopes

Do not assume `get()` identifies a path/domain source; use the recorded migration strategy.

Back to step 04
Capacity / eviction

A preference disappears or storage is evicted

Store only short enums and recover to a default. Cookies are not large-object or permanent user storage.

Back to step 03
D

Runtime and embedding

The code runs outside a browser or inside an iframe

SSR / SSG / Node

Keep browser access on the client

Build time has no `document`. If a server needs a cookie, use an explicit request API without exposing unrelated request values.

Third-party iframe

Assume storage can be restricted

Embedded contexts may partition or block storage. CHIPS/Storage Access requires a distinct need and compatibility review; it is not a sharing guarantee.

No JavaScript

Keep content and navigation reachable

Do not claim js-cookie can persist without scripts; static content, ordinary links, and basic boundary guidance remain readable.

Synchronous access

Do not read during every render

`document.cookie` is synchronous. Read and validate once at application entry, then use application state. Cookie Store is a separate async path that needs feature detection and a fallback.

Check browser versions separately

Verify read, write, removal, and HTTPS attributes for the supported browser matrix. This model is not browser certification and does not promise that cookies cannot be evicted.

E

Reset security and privacy scope

The purpose changes to auth, consent, or tracking

Stop using the preference path.

Servers set HttpOnly authentication cookies. SameSite affects sending and offers partial protection; it does not replace authorization and CSRF controls for sensitive writes.

Consent and analytics need a separate purpose, privacy-owner decision, field set, and retention policy. Define whether preferences persist across logout/account switching; this reference model treats them as account-independent while the server manages authentication separately.
